# Loan Eligibility Predictor — learning demo

> **Not for real lending.** This is an educational binary-classification demo using a synthetic dataset. It must never be used to approve, decline, price, or otherwise decide a real loan. Real lending systems need rigorous legal, privacy, fairness, security, governance, and ongoing validation controls.

## Dataset

The project uses Kaggle's [Loan Approval Classification Dataset](https://www.kaggle.com/datasets/taweilo/loan-approval-classification-data). The downloaded source file is retained unchanged at `data/raw/loan_data.csv`. The target is `loan_status` (`1` is the positive / approved class). ID-like columns are detected and removed before training; this dataset currently has none.

### Features

`person_age`, `person_gender`, `person_education`, `person_income`, `person_emp_exp`, `person_home_ownership`, `loan_amnt`, `loan_intent`, `loan_int_rate`, `loan_percent_income`, `cb_person_cred_hist_length`, `credit_score`, and `previous_loan_defaults_on_file`.

## Reproduce

Prerequisite: Python 3.10 or newer.

```powershell
python -m pip install -r requirements.txt
python src/train.py --threshold 0.50
python src/evaluate.py --model random_forest --threshold 0.50
```

Training makes a fixed stratified 80/20 split (`random_state=42`). Hyperparameters are selected only from the 80% training portion with stratified 5-fold cross-validation and ROC-AUC scoring. The 20% test portion is used only for the final report. Models and outputs are written to `models/` and `reports/`.

### Use the project

1. Clone or download this repository, then open a terminal in its root folder.
2. Create and activate a virtual environment (recommended): `python -m venv .venv`, then on PowerShell run `.venv\\Scripts\\Activate.ps1`.
3. Install the dependencies with `python -m pip install -r requirements.txt`.
4. Run `python src/train.py --threshold 0.50`. This trains both pipelines, performs the training-only 5-fold tuning, writes `reports/metrics.json`, creates `reports/figures/evaluation.png`, and saves reproducible local model files.
5. Inspect the outputs, or reload one saved model with `python src/evaluate.py --model random_forest --threshold 0.50`.

`models/*.joblib` is deliberately excluded from Git because those files are regenerated by the training command and can be large. The source CSV and example evaluation report remain in the repository.

## Preprocessing and models

One scikit-learn `ColumnTransformer` is embedded in each model pipeline:

- Numeric columns: median imputation, then `StandardScaler`.
- Categorical columns: most-frequent imputation, then `OneHotEncoder(handle_unknown="ignore")`.

Two models are compared: Logistic Regression is the interpretable linear baseline; Random Forest is a nonlinear comparison. See the generated `reports/metrics.json` for the exact selected hyperparameters and results.

## Evaluation

The generated evaluation artifact contains positive-class precision, positive-class recall, ROC-AUC, and a confusion matrix for each model. `reports/figures/evaluation.png` includes both ROC curves plus the Random Forest confusion matrix, which is the model with the highest test ROC-AUC in this run.

| Model | CV ROC-AUC | Test precision | Test recall | Test ROC-AUC |
| --- | ---: | ---: | ---: | ---: |
| Logistic Regression | 0.9534 | 0.7885 | 0.7475 | 0.9562 |
| Random Forest | 0.9731 | 0.8923 | 0.7745 | 0.9747 |

## Threshold choice

The default threshold is **0.50** as a neutral demonstration point. Increase it (for example, `--threshold 0.70`) to predict the positive class less often, which typically improves precision while reducing recall. Lower it (for example, `--threshold 0.30`) to capture more positives, which typically improves recall while reducing precision. Threshold selection must reflect a legitimate, reviewed goal—not an arbitrary automated lending rule.

## Fairness and limitations

Synthetic data cannot establish real-world fairness or performance. The data contains potentially sensitive or proxy variables such as gender, age, income, and home ownership; this demo does not establish that use of those variables is appropriate. It does not perform subgroup fairness testing, causal analysis, calibration testing, adverse-action reasoning, data-quality monitoring, drift monitoring, privacy review, or regulatory validation. Its scores are illustrative only and do not generalize to actual applicants.
